## บทที่ 2 ทฤษฎีและเทคโนโลยีที่เกี่ยวข้อง

### 2.1 เซิร์ฟเวอร์เสมือนบนคลาวด์ (Cloud VM)

ผู้ให้บริการคลาวด์แบ่งทรัพยากรของเครื่องจริงเป็นเครื่องเสมือนหลายเครื่อง ผู้เช่าได้สิทธิ์ผู้ดูแลระบบเต็มรูปแบบ แต่ต้องรับผิดชอบการติดตั้ง อัปเดต และป้องกันระบบเองทั้งหมด โครงงานนี้ใช้ Google Compute Engine [6] ซึ่งให้หมายเลข IP คงที่ (static IP) ได้ ทำให้ชื่อโดเมนชี้มาที่เครื่องเดิมได้ตลอด

### 2.2 LEMP stack

LEMP คือชุดซอฟต์แวร์สำหรับให้บริการเว็บ ประกอบด้วย Linux, nginx (อ่านว่า engine-x), MySQL และ PHP

- **nginx** รับคำขอ HTTP/HTTPS ส่งไฟล์คงที่เอง และส่งคำขอหน้า PHP ต่อให้ PHP-FPM [12]
- **PHP-FPM** (FastCGI Process Manager) รันโค้ด PHP ของ WordPress แยกเป็นกระบวนการต่างหาก [15]
- **MySQL** เก็บเนื้อหา ผู้ใช้ และการตั้งค่าของ WordPress เช่น ตาราง wp\_posts และ wp\_users [13]
- **WordPress** เป็นระบบจัดการเนื้อหา (CMS) ที่ต่อยอดด้วยธีมและปลั๊กอิน และมี REST API ให้โปรแกรมอื่นอ่านข้อมูลได้ [19]

### 2.3 ระบบชื่อโดเมน (DNS)

DNS แปลงชื่อโดเมนเป็นหมายเลข IP โดย A record ผูกชื่อกับ IPv4 หนึ่งหมายเลข Cloudflare ให้บริการทั้งจดโดเมนและ DNS พร้อม API สำหรับแก้ไข record ด้วยโปรแกรม ซึ่งโครงงานใช้ในการออกใบรับรอง HTTPS [4]

### 2.4 HTTPS, TLS และ ACME

HTTPS คือ HTTP ที่เข้ารหัสด้วย TLS เบราว์เซอร์ตรวจสอบตัวตนเว็บไซต์จากใบรับรอง (certificate) ที่ออกโดยหน่วยงานที่เชื่อถือได้ Let’s Encrypt ออกใบรับรองฟรีผ่านโปรโตคอล ACME (RFC 8555) [2] โดยผู้ขอต้องพิสูจน์ว่าควบคุมโดเมนจริง มี 2 วิธีหลัก [8]

ตารางที่ 2.1 วิธียืนยันการควบคุมโดเมนของ ACME

| วิธียืนยัน | วิธีทำงาน | ใช้ได้เมื่อปิดต่างประเทศ |
| --- | --- | --- |
| HTTP-01 | Let’s Encrypt เข้ามาอ่านไฟล์ที่เว็บไซต์ผ่านพอร์ต 80 | ไม่ได้ เพราะเครื่องตรวจอยู่ต่างประเทศ |
| DNS-01 | ผู้ขอสร้าง TXT record ที่กำหนด แล้ว Let’s Encrypt ตรวจที่ DNS | ได้ เพราะไม่ต้องเข้าเซิร์ฟเวอร์ |

โครงงานนี้ใช้ DNS-01 ผ่านโปรแกรม acme.sh [9] และ API ของ Cloudflare [4]

### 2.5 SSH และการยืนยันตัวตนด้วยกุญแจสาธารณะ

SSH เป็นโปรโตคอลเข้าควบคุมเซิร์ฟเวอร์แบบเข้ารหัส การยืนยันตัวตนด้วยกุญแจใช้คู่กุญแจ 2 ส่วน กุญแจส่วนตัว (private key) อยู่ที่เครื่องผู้ใช้เท่านั้น ส่วนกุญแจสาธารณะ (public key) เก็บไว้บนเซิร์ฟเวอร์ เซิร์ฟเวอร์ตรวจลายเซ็นดิจิทัลที่สร้างจากกุญแจส่วนตัวโดยไม่ต้องส่งความลับผ่านเครือข่าย จึงเดาไม่ได้และไม่มีรหัสผ่านให้ถูกขโมย ต่างจากรหัสผ่านที่อาจถูกเดาด้วย brute force [21]

### 2.6 Netfilter, iptables และ ipset

Netfilter เป็นส่วนกรองแพ็กเก็ตใน Linux kernel [11] โดย iptables เป็นเครื่องมือเขียนกฎ (rule) เป็นกลุ่มที่เรียกว่า chain แต่ละกฎกำหนดว่าจะ ACCEPT, DROP หรือ LOG แพ็กเก็ต ส่วน ipset [10] เก็บชุดหมายเลข IP จำนวนมากในโครงสร้างแบบ hash ทำให้ iptables เทียบกับทั้งชุดได้ด้วยกฎเดียว เร็วกว่าการเขียนกฎทีละช่วงมาก

รายการ IP ของแต่ละประเทศมาจากหน่วยงานที่แจกจ่าย IP ประจำภูมิภาค (RIR) สำหรับเอเชียแปซิฟิกคือ APNIC ซึ่งเผยแพร่ไฟล์สถิติ (delegated statistics) ที่ระบุประเทศของแต่ละช่วง IP [1]

### 2.7 fail2ban

fail2ban อ่าน log ของบริการต่างๆ เมื่อพบ IP ที่ทำผิดซ้ำตามเกณฑ์ที่กำหนด (เช่น เดารหัสผิดหลายครั้ง) จะเพิ่มกฎ firewall แบน IP นั้นชั่วคราว กฎแต่ละชุดเรียกว่า jail [5]

### 2.8 การยืนยันตัวตนสองปัจจัย (2FA)

2FA ให้ผู้ใช้ยืนยันตัวด้วยสิ่งที่รู้ (รหัสผ่าน) และสิ่งที่มี (รหัสจากแอปบนโทรศัพท์) ผู้โจมตีที่ได้รหัสผ่านไปจึงยังเข้าสู่ระบบไม่ได้ โครงงานใช้ปลั๊กอิน Two-Factor ของ WordPress [20]

### 2.9 การโจมตีเว็บที่พบบ่อย

ระบบตรวจจับในบทที่ 5 จัดประเภทการโจมตีตามแนวคิดที่ใช้กันทั่วไป เช่น OWASP Top 10 [14]

ตารางที่ 2.2 ประเภทการโจมตีเว็บที่ระบบตรวจจับ

| ประเภท | ความหมาย |
| --- | --- |
| SQL injection | แทรกคำสั่ง SQL ผ่านข้อมูลที่ส่งเข้าเว็บ เพื่ออ่านหรือแก้ฐานข้อมูล |
| Cross-site scripting (XSS) | แทรกสคริปต์ให้ไปทำงานในเบราว์เซอร์ของผู้ใช้คนอื่น |
| Path traversal | ใช้ ../ เพื่ออ่านไฟล์นอกโฟลเดอร์เว็บ |
| สแกนไฟล์ลับ | ไล่ขอไฟล์ที่มักเก็บรหัสผ่าน เช่น .env หรือ .git |
| User enumeration | ไล่หาชื่อผู้ใช้ WordPress เพื่อนำไปเดารหัส |
| Brute force | เดารหัสผ่านซ้ำๆ ทั้งหน้า login และ SSH |

### 2.10 โมเดลภาษาขนาดใหญ่ (LLM)

LLM เช่น Google Gemini [7] รับข้อความและตอบเป็นภาษาธรรมชาติ ใช้สรุปข้อมูลจำนวนมากให้คนอ่านเข้าใจง่าย ความเสี่ยงสำคัญคือ prompt injection คือการซ่อนคำสั่งไว้ในข้อมูลที่ AI อ่าน เช่น ใน log ที่ผู้โจมตีเป็นผู้สร้าง ระบบที่ใช้ AI อ่าน log จึงต้องแยกคำสั่งออกจากข้อมูลให้ชัดเจน
