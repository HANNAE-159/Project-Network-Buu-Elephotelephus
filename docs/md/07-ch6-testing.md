สิ่งที่พบ

- เหตุการณ์น่าสงสัยส่วนใหญ่เกิดที่ /wp-login.php IP อันดับหนึ่งคือ 64.227.79.185 (ต่างประเทศ) มี 1,004 เหตุการณ์ ได้แก่ ถูก geo-firewall บล็อก ถูกจำกัดความถี่ (429) ไล่หาชื่อผู้ใช้ และล็อกอินไม่สำเร็จ (ภาพที่ 6.6) ไม่พบการล็อกอินสำเร็จจาก IP นี้ใน log ช่วงที่ตรวจ
- IP 92.118.39.77 พยายามเข้า SSH ด้วยชื่อผู้ใช้ที่ไม่มีอยู่ และถูก fail2ban แบนอัตโนมัติ
- มีคำขอไฟล์ลับ (.env) และ xmlrpc.php ซึ่ง nginx ตั้งกฎปฏิเสธไว้ และการทดสอบจากภายนอกใน security-check.sh ยืนยันว่าถูกปฏิเสธ (หัวข้อ 4.4)
- ไม่พบ HTTP 5xx ใน access log ช่วง 24 ชั่วโมงที่ตรวจ (ยังไม่ได้วัดเวลาตอบสนองหรือความพร้อมใช้งานโดยตรง)

ข้อสังเกตสำคัญ: ช่วงวันที่ 28–29 ตุลาคม geo-firewall ปิดอยู่ชั่วคราว เพราะผู้ดูแลสั่ง apply ใหม่แต่ไม่ได้ยืนยันภายใน 3 นาที ระบบจึงย้อนกลับเองตามที่ออกแบบไว้ ในช่วงนั้นกราฟแสดงคำขอและเหตุการณ์น่าสงสัยพุ่งสูงทันที (ช่วง 20:00 และ 14:00–16:00) เมื่อเปิด firewall กลับมา เส้น “ถูกบล็อก” จึงเพิ่มขึ้นแทน เหตุการณ์นี้แสดงให้เห็นทั้งความสำคัญของ firewall และประโยชน์ของการป้องกันหลายชั้น เพราะระหว่างที่ firewall ปิด ยังมี rate limit, fail2ban และ SSH แบบกุญแจทำงานอยู่ และในช่วงเวลาที่ตรวจสอบ ไม่พบหลักฐานการเข้าสู่ระบบสำเร็จจาก IP ที่จัดเป็นผู้ต้องสงสัยใน log ที่รวบรวมไว้

นอกจากนี้ในตาราง IP พบ 34.124.128.152 ซึ่งเป็น IP ของเซิร์ฟเวอร์เอง ถูกนับเป็น IP ต่างประเทศ เกิดจาก WordPress เรียกตัวเองผ่านโดเมน (WP-Cron) แล้วถูก geo-firewall บล็อก คณะผู้จัดทำแก้โดยให้ geo-firewall อนุญาต IP ของเซิร์ฟเวอร์เองโดยอัตโนมัติ (ดูบทที่ 7)

### 6.3 การตรวจสอบคำแนะนำของ AI

AI สรุปว่า “พบการสแกนหาไฟล์ตั้งค่าความลับตระกูล .env และการค้นหาชื่อผู้ใช้ WordPress จาก IP ต่างประเทศอย่างต่อเนื่อง” คณะผู้จัดทำนำคำแนะนำมาตรวจกับระบบจริงก่อนนำไปใช้

ตารางที่ 6.3 ผลการตรวจคำแนะนำของ AI

| คำแนะนำของ AI | ผลการตรวจ |
| --- | --- |
| ตั้งค่าเว็บเซิร์ฟเวอร์ให้ปฏิเสธไฟล์ .env | ทำไว้แล้วตั้งแต่ติดตั้ง (location \~ /.) |
| บล็อก IP ที่สแกน และพิจารณา GeoIP blocking | มี geo-firewall และ fail2ban อยู่แล้ว คำแนะนำนี้เกิดจาก AI ไม่ทราบบริบท |
| ปิดการไล่หาชื่อผู้ใช้และจำกัด REST API | ถูกต้อง ณ เวลาที่ได้รับคำแนะนำยังไม่ได้ปิด ต่อมาปิดในธีมเวอร์ชัน 3.7.0 และตรวจผลสำหรับผู้ที่ไม่ได้ล็อกอินแล้ว (หัวข้อ 4.4) |

คณะผู้จัดทำจึงปรับให้สคริปต์ส่งรายการมาตรการที่มีอยู่ และ status code ของแต่ละคำขอให้ AI ด้วย ผลคือ AI ต้องใช้ควบคู่กับการตัดสินใจของคน ไม่ควรเชื่อตามทุกข้อ


### 6.4 การตรวจสอบเพิ่มเติมหลังปรับตัวเก็บข้อมูล

ข้อมูลในหัวข้อ 6.2 และภาพที่ 6.3–6.6 เป็นหลักฐานจากรอบก่อนปรับตัวเก็บข้อมูล ส่วนตารางที่ 6.4 เป็นข้อมูลจริงจากการรันตัวเก็บข้อมูลรุ่นแก้ไขเพียงรอบเดียว เมื่อวันที่ 29 ตุลาคม 2569 เวลา 23:32:58 น. เขตเวลา Asia/Bangkok (UTC+07:00) อ่านจากไฟล์ summary.json ที่คัดลอกเก็บทันทีหลังรันเสร็จ ไม่ใช่ภาพหน้าจอ dashboard รอบใหม่

ก่อนติดตั้งได้สำรองสคริปต์และข้อมูลเดิมบนเซิร์ฟเวอร์ ตรวจไวยากรณ์ Python และติดตั้งด้วยสิทธิ์ root ตามเดิม รุ่นนี้นับจำนวนคำขอด้วยขอบช่วงเวลาเดียวกับสถานะ HTTP และตัด IP สาธารณะของเซิร์ฟเวอร์เองออกจากรายการเหตุการณ์ ผลตรวจสอบเชิงตัวเลขสรุปดังตาราง
