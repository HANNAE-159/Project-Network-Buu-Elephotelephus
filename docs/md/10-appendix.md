## ภาคผนวก

### ภาคผนวก ก คำสั่งตรวจสอบระบบ

คำสั่งเหล่านี้ใช้เก็บหลักฐานในบทที่ 6 และใช้สาธิตต่ออาจารย์ได้

```bash
# ขั้น 1: SSH
sudo sshd -T | grep -Ei 'permitrootlogin|passwordauthentication|authenticationmethods'
ssh root@34.124.128.152            # ต้องได้ Permission denied
last -n 20                          # ประวัติการเข้าเครื่อง

# ขั้น 1: เวอร์ชันและบริการ
sudo cat /root/versions.txt
sudo fail2ban-client status
sudo ss -ltnp | grep 3306           # ต้องเป็น 127.0.0.1:3306

# ขั้น 2: firewall
sudo bash geo-firewall.sh status
sudo journalctl -k --since -1d --grep GEO-BLOCK | tail

# ส่วนเพิ่ม: secdash
sudo python3 /usr/local/sbin/secdash-collect.py
```

| inc/secdash.php | หน้า dashboard “ความปลอดภัย” ในหลังบ้าน |
| inc/hardening.php | ปิดการไล่หาชื่อผู้ใช้ ซ่อนเวอร์ชัน ปิด XML-RPC และข้อความล็อกอินผิดแบบไม่เปิดเผยชื่อผู้ใช้ |


### ภาคผนวก ง หลักฐานการทดสอบเพิ่มเติม

ทดสอบวันที่ 29 ตุลาคม 2569 โดยใช้สิทธิ์ที่มีอยู่เดิม ไม่มีการเปลี่ยนรหัสผ่านหรือเปิดพอร์ตเพิ่ม

การทดสอบการแสดงผลใช้ Chromium ผ่านเบราว์เซอร์ในแอป บน Windows กำหนด viewport 1440 × 900 และ 390 × 844 พิกเซล ค่าความกว้างพื้นที่เนื้อหาไม่รวมแถบเลื่อนคือ 1425 และ 375 พิกเซลตามลำดับ ทั้งสองกรณี scrollWidth เท่ากับ clientWidth จึงไม่พบการล้นแนวนอน และไม่พบภาพที่โหลดเสร็จแต่มี naturalWidth เป็นศูนย์ เมนูที่ขนาดมือถือมีสถานะขยายหลังเปิดและยุบหลังปิด ข้อจำกัดคือทดสอบหน้าแรกกับเมนู และจำลองขนาดหน้าจอ ไม่ได้ทดสอบอุปกรณ์มือถือจริงหรือทุกหน้า

ทดสอบข่าวซ้ำผ่าน WP-CLI ด้วยผู้ใช้ www-data เรียก buu_import_news() ซึ่งเป็นฟังก์ชันเดียวกับปุ่มนำเข้าในหลังบ้าน เริ่มเวลา 23:32:24 และสิ้นสุด 23:32:32 น. UTC+07:00 ใช้ SQL นับโพสต์ทั้งหมด นับโพสต์ที่มี _buu_src และจัดกลุ่ม URL ต้นทางเพื่อหา URL ที่ผูกกับหลายโพสต์

ตารางที่ ง.1 ผลทดสอบนำเข้าข่าวซ้ำสองรอบ

| ช่วงตรวจ | โพสต์ทั้งหมด | โพสต์นำเข้า | URL ต้นทางซ้ำ |
| --- | --- | --- | --- |
| ก่อนนำเข้า | 111 | 101 | 0 กลุ่ม |
| หลังรอบที่ 1 (ใหม่ 0 ข้าม 100) | 111 | 101 | 0 กลุ่ม |
| หลังรอบที่ 2 (ใหม่ 0 ข้าม 100) | 111 | 101 | 0 กลุ่ม |

ผลทั้งสองรอบไม่มี error และ pending เป็น 0 การทดสอบนี้ยืนยันการข้ามข่าวเดิมในรายการที่ API ส่งกลับสองรอบ ไม่ได้ยืนยันทุกกรณี เช่น การนำเข้าพร้อมกันหลายกระบวนการ การที่โพสต์นำเข้าสะสมมี 101 ข่าวไม่ขัดกับเพดาน API 100 ข่าวต่อรอบ เพราะเป็นคนละขอบเขตการนับ
